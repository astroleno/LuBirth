# 星空信源与展示：综合选型建议

日期：2026-10-22。方案已获用户“你要不开始做吧”批准，首轮已在独立 spike 实施；详见[实施与验证记录](../../docs/handoff/2026-10-22-sky-implementation.md)。后续已完成玉皇庙 28 幅原型 + 28 幅细线稿，见[完整交付与验证记录](../../docs/handoff/2026-10-22-yuhuang-28-pairs.md)。本文保留完整目标；宿界等未核实项目不因图绘完成而视为完成。承接[跨平台调研](2026-10-22-research.md)和[既有交接](../../docs/handoff/2026-10-21-history-and-sky.md)，仍不接入主页面。

## 1. 选择结果

采用现有 Three.js / React Three Fiber / astronomy-engine 架构，以真实星表承载星位，以有版本的文化数据承载星官，以独立图绘承载艺术表现。参考库中的 48 个条目按用途取舍，不拼成多套引擎。

| 用途 | 选择及信源 | 展示与边界 |
| --- | --- | --- |
| 星位、星等与冷暖 | 继续使用已冻结的 [HYG v4.4](https://codeberg.org/astronexus/hyg) 和现有 [astronomy-engine](https://github.com/cosinekitty/astronomy) 计算；Stellarium 桌面端用于独立对照 | 星等取目录 V 值，颜色以 B−V 为依据；曝光、光晕和缩放是显示映射。日期改变不自动改变目录星等或本色 |
| 中国星空 | 以现有 [Stellarium 宋代星官重建](https://github.com/Stellarium/stellarium/tree/023040b5241badc9ea0b29428e3ef3f35d2fc65b/skycultures/chinese_song_dynasty)为默认文化包 | 展示三垣、二十八宿主星官及其余星官；明确写“宋代星官·现代重建”。二十八宿作为同一文化包的重点层，不拆成互不关联的名单 |
| 现代星空 | [Stellarium v26.3 Modern](https://github.com/Stellarium/stellarium/tree/v26.3/skycultures/modern) 的名称、连线与图绘；[IAU](https://www.iau.org/IAU/Astronomy-FAQs/Constellations.aspx)定义区域；[CDS VI/49](https://cdsarc.cds.unistra.fr/viz-bin/ReadMe/VI/49?format=html&tex=true)作为边界数据候选 | 88 星座独立切换；现有 85 条图像映射保留真实缺项，不伪造补齐。区域边界、连线和插画分别控制 |
| 银河与空间氛围 | [NASA SVS Deep Star Maps 2020](https://svs.gsfc.nasa.gov/4851/)作为真实密度、配色与坐标配准的底稿 | 加工为去除显著亮星的弥散背景，与目录星点分工；不用含线条、名字、边界的成图作底图。静态 J2000 图不能替代古代亮星位置计算 |
| 中国星君图绘 | 原创完整二十八宿图绘，造型优先研究[晋城博物馆玉皇庙资料](https://jcbwg.cn/bwg/zx/fchd/202607/t20260708_2368588.shtml) | 主要参考元代二十八星君彩塑的冠服、动物和法器；绘制适合天球的图像。标成当代创作与造型参考，不标成宋代原画 |
| 古人、月夜事件 | [CBDB](https://cbdb.hsites.harvard.edu/download-cbdb-standalone-database)用于发现候选；原始文献的可定位版本为日期证据，机构资料与[CHGIS](https://chgis.fas.harvard.edu/pages/database)辅助人物、地名复核 | 原历日期、换算日期、事件地点与观测时刻分开。只有精确到日且经过核验的记录，才能进入确定日期的体验入口 |

现代星座是天区，连线是图形表达，插画是文化图绘，三者不可互相代替。中国宿界另有历史体系与距星问题；不能沿用现代星座边界，也不能画成等宽的 28 个扇区。印度 27 宿若以后需要，应另设文化包。

保留当前星点材质：细亮星核、可辨冷暖、柔光和缩放适配。先用真实银河背景、视域内多幅图绘和名称层次提升完成度；新增光效是否值得，依据画面与帧时对照决定。

## 3. 信源怎样保存、怎样给人看

沿用现有数据 manifest 和 reference/catalog 的思路，补对象与证据的对应关系。每个来源保存作者／机构、标题、版本或固定提交、直达链接、访问日期、许可与加工说明；一条资料可支持多个对象，一个对象也可有多个来源。

**核实状态落实到具体字段。** “读到原历生日”“换算已复核”“出生地为县域”“出生时刻不详”分别记录，不能用一个“已核实”覆盖整条人物资料。参考项目的“已读实现”与“已经运行验证”也继续分开。

| 内容 | 必须保留的证据 | 用户看到的内容 |
| --- | --- | --- |
| 恒星 | 目录版本、原始标识、星等／颜色字段、缺值与代理映射 | 默认显示名字；详情可查数据来源。缺失颜色使用中性白，不编造本色 |
| 星官／星座 | 文化名称、适用历史体系、重建作者、线条版本与依据 | “宋代星官·现代重建”等短说明；展开后可查重建说明和原始出处 |
| 星君图绘 | 创作者、创作版本、参考文物或文献、图片许可、恒星锚点 | “当代图绘；造型参考玉皇庙元代彩塑”。图像依据与星位依据分别列出 |
| 人物／事件 | 原文短摘、卷页／版本、原历与闰月、换算输入输出及独立复核、地点类型与范围、时刻精度 | 日期说明、地点精度、来源链接；演示钟点明确为用户选择 |

CBDB 是发现与索引入口，不能把总人数当精确生日人数；其公开下载页也列出非商业等利用条件，不直接将学术版整库作为产品可分发数据库。古籍整理、图片和坐标整理的利用条件各自保留。

界面采用“选中对象 → 来源与说明 → 同一详情区域展开”的路径。出处跟着具体名字、日期或图绘，不只藏在一个全站致谢页里。内容可排成：

> 心宿  
> 宋代星官 · 现代重建  
> 星官资料：Stellarium 宋代文化包，作者及参考文献可展开。  
> 图绘资料：创作完成后展示作者、造型依据和许可。  
> [来源与说明]

这只是内容示意，不表示心宿图绘已经制作。具体史料要回到卷页核对；Stellarium 的重建说明不能替代对原书的阅读。

## 4. 展示方案

### 4.1 两套文化，共用一片真实星空

文化切换为“中国星空 / 现代 88 星座”。中国模式的默认说明是“宋代星官·现代重建”，不随所选历史日期暗中换文化，更不暗示所有朝代都使用这一套星图。

中国模式在概览中建立三垣、四象与二十八宿的层次，缩放后逐步出现所属星官和恒星名字。“二十八宿重点”只是过滤显示，完整星官数据始终保留。宿区与月亮落宿须有同一历史体系的距星、边界证据后再启用；目前不能标为已完成。

现代模式覆盖 88 个条目，已有图绘按真实映射呈现。默认不让全部区域线占满天空；需要研究天区时再打开区域边界。

### 4.2 天空里就能看到图绘

| 状态 | 画面 |
| --- | --- |
| 概览 | 星光与银河为主，图绘低透明度显现，名称稀疏，能感到完整天区结构 |
| 中等缩放 | 视域内数幅相邻图绘同时可见，星官／星座连线和主要名字清楚；不必逐个点开才能发现图像 |
| 选中对象 | 当前图绘和连线适度突出，邻近图绘退淡，主星保持清晰；详情沿现有控制带展开 |
| 继续放大 | 更多恒星细节与名字出现，亮星仍是有光晕的点；图绘不会脱离恒星漂在屏幕上 |

图绘从创作时就按照真实星形构图，以至少三个分布合理、不共线的恒星锚点建立映射，并用额外星点检查贴合。玉皇庙实物用于研究形象；不将彩塑照片直接拉伸成星座。现代图绘继续沿用已有天球投影能力，再增加视域加载、透明度渐变与缓存管理。

建议中国图绘采用深靛夜空中的低饱和金色细线，辅以少量矿物色晕染；人体、兽形与衣带留出星点的位置，避免整片厚重画像盖住天空。恒星冷暖仍由目录数据决定。提供关闭图绘的纯星图状态。

### 4.3 界面维持一个主要玻璃表面

底部一条轻量玻璃控制带收纳时间、地点、文化切换和图层。选中后，**同一表面展开为详情**；查看出处再在其中展开文本，不新增多层外框。

星空中的地名、星名、星官名直接排字，不加外框。按钮统一圆角矩形，玻璃的模糊、高光和边缘厚度保持一致。标签同时避让其他标签、选中图绘重点与控制带，显隐有短暂延迟，避免临界位置闪烁。

手机保留充分的可视天空，选中目标定位到详情上方的可见区域。适配真实安全区、横竖屏与双指缩放；iPhone Safari 真机另行验收。

### 4.4 古人同望与历史上的今天

它们作为经过核验的日期入口，进入后共享时间、地点和选中对象，不在天空上叠满人物卡。日期页显示“原历 / 换算日期”，地点区分出生地、籍贯与事件发生地；只有县域证据就展示范围。

只知日期时，让用户选演示钟点，明确为天空重建，不把 00:00 当出生时刻，也不推断该人物当时实际看见了月亮。“历史上的今天”默认按注明规则的换算公历月日匹配；原历纪念日另作明确模式，不能混用。

## 5. 模块与关键接口

下表是职责边界，优先由现有文件承接，不要求新建另一套通用引擎。

| 职责／接口 | 输入与输出 | 约束 |
| --- | --- | --- |
| 数据生产与来源记录 | 固定星表／文化包 → 现有 catalog、manifest、对象关联的 sourceRefs 和字段级证据 | 当前 HYG v4.4、宋包提交、Modern v26.3 保持冻结；升级单独核差异。当前保留 8,945 星，339 是绘图记录数，不是历史星官总数 |
| SkyFrame／星点 | 目录、UTC、观测地点 → 同一坐标约定下的方向与显示属性 | 沿用 skyModel、SkyObjects、starAppearance；图绘与星点共享坐标，不改星位来迁就画面 |
| 文化与边界层 | cultureId、条目、已核实边界 → 名称、连线、可选区域 | 中国主星官与宿区分开；现代边界使用声明的原始历元与转换路径。CDS 已读 ReadMe，数据文件尚未导入／验证 |
| 图绘层 | artworkId、所关联对象、恒星锚点、视域与选择 → 天球图绘和加载队列 | 从仅显示选中图绘扩展到视域内多幅；按解码尺寸管理纹理预算，优先当前对象，避免一次加载全部图 |
| 选择与详情 | 对象 ID、当前文化／日期、sourceRefs → 一个详情区域的内容 | 星位、文化故事、图绘来源和日期证据各有归属；提供直达出处 |

银河背景需要独立坐标配准，并在加工时检查亮星残留，避免与点星双重计亮。资源质量可按设备降低背景分辨率、DPR 和光效成本；目录位置、文化内容和可选择对象保持完整。

继续只在 sky-spike.html 中验证。未来接入原版须明确观测入口及相机关系，保留已确认的地月构图；天球和相机不挂到地球旋转组，不引入额外月球灯光。

## 6. 迭代顺序与验收

1. **信源与文化结构。** 整理对象—出处关系、文化层级和字段级状态；核对完整中国星官与现代 88 条目。宿界、历法和出生地点作为有明确证据要求的数据工作处理。
2. **完整星图体验。** 在 spike 扩展视域内多图绘，加入经过配准、去亮星处理的银河背景，完成标签避让和同一玻璃表面的详情。先用现有现代图绘检验构图、锚点和资源预算。
3. **中国二十八宿图绘。** 先用两幅不同星形的样张检验画法与天球贴合，再扩展完整 28 幅；两幅样张不算最终交付。每幅具备形象依据、作者与锚点记录，保持三垣和其余星官的完整呈现。
4. **经核验的人物与事件入口。** 按同一日期、地点和来源标准扩库；进入体验的记录必须通过相应核验。主页面接入另行按已确认构图与功能验收。

建议验收标准：

- 名称、连线端点、图绘锚点都可追溯；保留两处成分星代理与 M7／M44 未绘制的明确说明，不把当前缺口写成已解决。
- 现代完整 88 条目；中国完整文化结构与最终 28 幅图绘。宿区须核定历史体系、距星与边界后验收，不能用主星官连线代替。
- 25°、70°、110° 视场及不同 DPR 下，图绘与锚点持续贴合；亮暗与冷暖差异可辨，星点放大后仍保持点光源观感。
- 同一主要玻璃表面容纳控制、详情和出处；地名、星名无框；标签不覆盖选中对象的关键部分。
- 沿用现有单画布、按需绘制与 30 Hz 档。建议同设备同宿主交互绘制间隔 P95 ≤ 40 ms；加载和渐变结束后静置不持续绘制。报告冷启动、持续交互和多次切换的纹理占用，不只取一个正常窗口。
- 手机模拟与 iPhone Safari 真机结果分开；真实横竖屏、双指、安全区、后台恢复及持续性能是独立验收项。
- 原历、换算、地点和时间各有证据与精度说明；不能以“精确到日期”推导出生钟点或全古代星位已经精确验证。

## 7. 选型时的证据边界

本节保留实施前的研究状态。银河与两幅中国图绘的最新实施、实测及缺口，以[首轮实施记录](../../docs/handoff/2026-10-22-sky-implementation.md)为准。

本轮复核了本地数据说明、manifest、现有图绘实现及交接第 8／9 节，并重读了 Stellarium、NASA、Star Walk、CBDB、IAU、CDS 与候选项目的相关官方资料。玉皇庙官方文章的检索结果提供了正文；直接页面打开未成功，未取得图像素材或授权。

IAU 旧地址已失效，本文使用新的官方 FAQ 地址。CDS VI/49 的 ReadMe 提供 B1875 和 J2000 表及修订记录；真正采用时仍需固定文件版本、校验值并核查边界连续性。

新调研的外部演示未运行验证，不能据其作者描述承诺本项目帧率。现有 spike 的现代星位抽样对照已在交接第 8 节记录；古代天狼星／南门二仍有最大约 6.88′ 的差异，不能扩大为全古代目录已通过。iPhone Safari 真机尚未验收。中国星君图绘、银河背景、完整宿区及人物日期入库也都没有因本次选型而自动完成。
