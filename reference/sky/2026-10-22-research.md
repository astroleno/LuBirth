# 星空、星座与中国星宿：跨平台深度调研

日期：2026-10-22  
范围：LuBirth 独立星空 spike 的后续参考；本轮仅调研与保存资料。  
入口：[全部来源与状态](catalog.json) · [检索与核查日志](search-log.md) · [前期天文与历史交接](../../docs/handoff/2026-10-21-history-and-sky.md)

## 结论

当前差距涉及完整星图体验：恒星明暗冷暖、银河与尘埃、星座/星官连线、人物或动物图绘、缩放层级、选择反馈和文化解释。继续单独调整星点，不能补齐这些层次。

本轮完成四轮检索，覆盖 Codrops、Awwwards、OpenProcessing、CodePen、Steam、GitHub、Shadertoy、CodeSandbox、Dribbble，并补充作者和官方资料。清单共 **48 条参考与排除记录，其中 41 条为本轮新增，7 条保留前轮基线**。每条记录都说明用途、证据强度、天文依据和许可状态。

清单中的“已读实现”包含相关示例或结构化数据，并非整个仓库审计。没有对这些演示执行浏览器交互、录帧、iPhone 实测或安装 Steam 应用；作者的性能数字均不作为我们的测量结果。动态 GIF 也未完成目视评审。

### GitHub：已有贴近目标的中国网页项目，但展示方式需要分清

GH-01 的 [SOURCES.md](https://github.com/SenTomoHiro/twenty-eight-mansions-star-map/blob/main/SOURCES.md) 区分现代星表、宋代星官与宗教文化资料。它固定了 Stellarium 26.2 的上游数据，并保留来源和不确定性说明。

进一步读到的 [DeityStage.tsx](https://github.com/SenTomoHiro/twenty-eight-mansions-star-map/blob/main/src/features/xingxiu/DeityStage.tsx) 使用普通图片构成人物展示舞台，包含手机图片回退；这部分不能当作已经完成 Star Walk 式天球图绘。[skyLabelCollision.ts](https://github.com/SenTomoHiro/twenty-eight-mansions-star-map/blob/main/src/features/sky/skyLabelCollision.ts) 有标签碰撞、显隐滞回和缩放限制，可参考其处理相邻标签闪烁的思路。

该项目的 [第三方声明](https://github.com/SenTomoHiro/twenty-eight-mansions-star-map/blob/main/THIRD_PARTY_NOTICES.md) 明确：28 幅数字神像没有单独开放素材许可，不能把 Stellarium 数据的 CC BY-SA 授权套到插画上。

GH-02 的[距星与精度说明](https://github.com/yoshimoto-ri/digital-armillary/blob/main/README.md)很有价值，但“历代距星关系”是作者的研究论断。本轮未复现其验证，也没有据此认定可替代历史天文学核验。其忽略恒星自行的限制，对“古人同望”尤其需要保留。

GH-06 [three-starmap](https://github.com/mathiasbno/three-starmap) 是体量较小的组织参考。作者承认部分星表映射失败会跳过，所以不能仅凭“88 星座”介绍认定映射完整。GH-12 [Cosmos Explorer](https://github.com/Arrbel/cosmos-explorer/blob/main/requirements.md) 的相关命中主要来自需求稿，本轮没有验证对应功能已经交付。

### Shadertoy：最直接的缩放候选是数据编码，不是叠更多光晕

SH-01 的[作者说明](https://www.reddit.com/r/GraphicsProgramming/comments/1j7uvc9/pointlight_star_texture_1tap/)针对普通星图纹理放大后像素化的问题，提出把星点的亚像素位置、颜色和亮度存进纹理，用自定义 mip 编码保留不同尺度上的亮星位置。作者也明确说当前演示的星位随机，只模拟亮度和颜色分布。

对我们的价值是研究“缩放时保留点光源”的方法。下一步至少要核对：

- 原作实现、原作许可和实际采样方式；
- 真实 HIP 星表如何编码，是否保留需要显示的星官成员；
- 多颗星落在同一纹素、近双星和明暗交界时是否丢失信息；
- 110°、60°、25° 等视场与不同 DPR 下的连续性。

SH-02 [Star Nest](https://www.shadertoy.com/view/XlfGRj) 与 SH-03 [Simplicity Galaxy](https://www.shadertoy.com/view/MslGWN) 适合研究弥散云气、暗区和色彩层次。读到的[Defold 移植教程](https://defold.com/tutorials/shadertoy/)和[分发源码](https://sources.debian.org/src/kodi-visualization-shadertoy/21.0.2%2Bds-1/visualization.shadertoy/resources/shaders/simplicitygalaxy.frag.glsl)不提供真实星位。嵌套迭代的全屏成本也需要专项测量，不能用演示效果代替手机性能证据。

许可仍有待补齐：Defold 教程里的移植代码标 MIT，原 Shadertoy 页面未读取成功，本轮没有据此认定原作许可。分发仓库或播放器的总许可同样不能自动覆盖每个原始 shader。

### 银河氛围：先分清从哪里看银河

Codrops 的 [Particles Galaxy](https://tympanus.net/codrops/2022/06/21/creating-a-particles-galaxy-with-three-js/) 和作者示例中的 [Galaxy Generator](https://www.safinettah.com/experiences/galaxy-generator) 多为从外部看盘状星系。它们可参考疏密、颜色和粒子组织，不能整套替换地球所见的天幕银河带。

GH-03 的[具体实现](https://github.com/vercel-labs/nextjs-nights-shader/blob/main/components/galaxy/galaxy.tsx)更接近天幕组织：两条密集带加稀疏星场、实例化四边形、FOV/分辨率参与尺寸计算、半分辨率泛光。读到的默认参数合计约 146,000 个实例，这只是代码配置，未证明能在我们的目标手机达到预期帧率。悬停流体、Logo 遮罩和随机星点也不是我们的天文数据层。

这里还发现一个需要反证的兼容性问题：项目 README 要求 WebGPU 并称无 WebGL 回退；[Three.js 官方文档](https://threejs.org/docs/pages/WebGPURenderer.html)则明确 WebGPURenderer 可回退 WebGL2。必须检查项目锁定版本及其具体节点，再运行验证；不能仅凭包名宣布它只支持 WebGPU，也不能反过来保证整个示例可回退。

[NASA Deep Star Maps 2020](https://svs.gsfc.nasa.gov/4851/)提供有真实位置、亮度、颜色和天球投影依据的基准，适合对照银河取向及密度。它仍是静态 J2000 天图；与单独的亮星点云叠加会重复计亮，也不能独自承担古代星位复原。

### 图绘：西方人物、东方四象、二十八星君是不同的素材层

[Matt Huynh 的 Constellation Tiger](https://dribbble.com/shots/4383553-Constellation-Tiger) 是本轮最贴近东方星图轮廓方向的新线索：作者说明灵感来自中国星图白虎。它值得研究动物轮廓与星点的关系，但只有单作，不能算完整四象或二十八宿图库。

[Sara Lynn Cramb 的 Night Explorer](https://dribbble.com/shots/4171113-Night-Explorer-Star-Map-Northern-Hemisphere)可参考科普图绘和标注层次；[Purrweb 的星图概念](https://dribbble.com/shots/23106714-Educational-Web-Platform)可参考功能表达。两者都没有被当成可运行的星图引擎。

晋城府城玉皇庙的馆方资料应按**元代二十八星君彩塑**研究。[馆方线上展览入口](https://jcbwg.cn/bwg/szzl/xszl/)及其链接的[东方星空艺术展](https://www.720yun.com/vr/0dfjerkOrw1)可用于后续造型考证。若最终需要原创系列，应逐尊整理名称、动物属性、姿态、衣冠和器物；星位锚点另由选定的星官体系确定。四象轮廓、人物星君和古星图原件分别保留出处，不互相冒充。

### CodePen、CodeSandbox：可读示例也要检查数据语义

[Constellation Explorer](https://codepen.io/Nidal95/pen/NPWYWOW)有星座切换、星名提示、亮度和神话说明。读到的实现只提供 7 组手写点位，背景随机，不能作为完整星图或历史坐标来源。

[Drei Stars 的实现](https://github.com/pmndrs/drei/blob/master/src/core/Stars.tsx)随机生成位置和尺寸，颜色按点序号分配，默认饱和度为零。它有可参考的软边点精灵和输出处理，但并未提供真实星等和 B−V。把该组件放进画面不能解决用户要求的真实亮暗冷暖差异。

Safi Nettah 的[作者页面](https://www.safinettah.com/experiences/galaxy-generator)公开 R3F 示例并提供 CodeSandbox 入口。可读代码支持我们研究径向色彩和点云缓存，沙盒本身未能打开。其余两个 CodeSandbox 入口只保存为检索线索，未当成已经验证的组件。

### Steam、Awwwards：产品表现与叙事参考

[SpaceEngine](https://store.steampowered.com/app/314650/SpaceEngine/)适合后续观察尺度切换和星云层次；开发者明确区分目录对象与未知区域的程序生成对象。[Star Chart](https://store.steampowered.com/app/460580/Star_Chart/)可参考星座图绘与浏览，它不是 Star Walk。[PlanetariumVR](https://store.steampowered.com/app/1313970/PlanetariumVR/)的介绍展示了星座、网格和学习内容如何分层。

[CAPCOM GO!](https://store.steampowered.com/app/1116650/)适合历史主题与天文馆式叙事。开发者明确说明其 Starball 模式并非完全准确的夜空模拟，不作为星位验证对象。

Awwwards 的 [All I Wish You](https://www.awwwards.com/sites/all-i-wish-you)将人的祝福组织成星群，与“古人同望”的人物/事件入口有叙事关联；[Aurora](https://www.awwwards.com/sites/aurora-1)可参考时间、环境与声音结合。它们属于产品或历史案例参考，没有据此找到可直接复用的中国精确星图实现。

## 保留的天文与文化基线

- [Stellarium Web Engine](https://github.com/Stellarium/stellarium-web-engine)：完整星图能力的对照。官方 HTML 示例演示星文化、恒星、银河、地景等数据源分开加载；桌面新版文化包到 Web 的兼容性仍需验证。
- [Stellarium 26.3 skycultures](https://github.com/Stellarium/stellarium/tree/v26.3/skycultures)：传统中国、陈卓、宋、元、《象林》有不同时代依据。本轮沿用前轮核对结果：这五包的天球图绘记录均为 0，说明页历史星图插图另计。
- [Modern Chinese](https://github.com/Stellarium/stellarium/tree/v26.3/skycultures/modern_chinese)是现代 88 星座配传统中国星名，85 条图绘仍属西方星座。
- [Journey to the West](https://github.com/Stellarium/stellarium/tree/v26.3/skycultures/modern_journey_to_the_west)是当代西游演绎，说明覆盖 84 个现代星座，索引有 81 条图绘，许可 CC BY-NC-ND 4.0。
- [D3-Celestial 中国演示](https://ofrohn.github.io/celestial-demo/chinese.html)：312 条星官标注、28 个宿区多边形是公开 JSON 记录计数，宿界的历史依据待核。
- 中国二十八宿与[印度 Nakshatras 的 27/28 体系](https://github.com/Stellarium/stellarium/tree/v26.3/skycultures/indian_nakshatras)分别处理，不能互相删补。
- [Star Walk 官方图绘与视觉效果说明](https://starwalk.space/en/tutorials/how-to-use-visual-effects)作为完整体验目标；未找到可直接采用的官方开放网页 SDK 或图集许可。

## 后续独立 spike 的研究包

这些是后续可另行安排的验证任务，本轮未执行集成或绘图。

| 研究包 | 输入 | 应交付的证据 |
|---|---|---|
| 完整星图交互 | Stellarium Web、SkyEngine、星图产品案例 | 同星区/同视场的选择、聚焦、缩放、标签与图绘对照；明确哪些功能实际运行过 |
| 缩放后的星点 | 现有真实星表、SH-01、GH-03 | 相同亮星在多视场/DPR下的半径、亮度和冷暖变化；密集星保留情况 |
| 真实银河＋艺术氛围 | NASA 天图、GH-03、分形背景候选 | 天球取向对齐、与亮星不重复计亮、背景强度分档及手机成本 |
| 中国星空完整性 | 官方分时代文化包、GH-01、GH-02、D3 | 主星官、距星、宿界、时代说明与完整数据计数；不以“有28个菜单项”代替验收 |
| 图绘方向与来源 | 西方完整图绘、白虎作品、玉皇庙馆方资料 | 轮廓/人物方案对照、星点锚定办法、全套素材缺口与逐项许可 |
| 手机验证 | 上述候选的独立页面 | iPhone设备/系统/浏览器版本、加载与显存/帧时、连续拖动缩放、后台恢复；实测与作者声称分开 |

当前主页面、地月构图、光照架构和发布状态均未因这份调研改变。正式实现仍需在已确认目标、模块接口和验收标准内推进。

## 阅读清单的方法

- 先读新增短名单，再按 catalog.json 的平台、优先级和证据字段筛选。
- 11 条为已读相关实现/数据，2 条为已读移植实现，1 条核对作者说明，10 条为作者/官方文档，15 条为项目页，9 条仅为检索线索；统计含前轮基线。
- 动态主分支链接记录的是本次所见内容；后续要复现实验时固定具体提交和依赖版本。
- 公开仓库、可运行演示、开放素材许可分别核实。完整二十八星君图绘仍有选型与授权缺口。
