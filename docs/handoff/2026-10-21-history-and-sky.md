# 古人同望：信源、候选记录与星空渲染交接

研究与交接日期：2026-10-21。范围：公开资料的信源发现、简单核实、候选整理，以及独立星空背景 spike。此文不是已完成入库的数据集，也不授权后续 agent 自动提交、推送或发布。

## 1. 当前结论与状态标记

- 中国人物先交接 **14 条生日候选**，另附牛顿的双历对照；事件先交接 **13 条日期候选**。另有规模化扩充入口，见第 2 节。
- “精确到日”首先指**原始历法有月、日记录**。中国候选尚未逐条独立完成原历 → 儒略日 → 统一公历的计算复核。不能把表中原历直接传给 JavaScript `Date`。
- 中研院两千年中西历转换工具在本次访问中返回 401 / IP 被封锁页面，因此日历换算保留为待核实；没有绕过访问限制。故宫乾隆的双历日期、牛顿的双历日期已找到机构明确对照，仍须区分“机构给出对照”与“我们重新计算通过”。
- 多数地点目前只核实到地名、宫室或区域，**没有完成现代经纬度审校**。籍贯、任职地、行旅地不自动等于出生地。

标记含义：

| 标记 | 含义 | 能否直接入正式库 |
| --- | --- | --- |
| **已见原历日** | 已读到来源中的具体月日；仍可能需要版本、注释或真伪复核 | 只能存为带出处的候选 |
| **机构双历** | 机构页面明确列出原历与西历对照 | 可作为换算对照样本，不能声称已独立重算 |
| **历法待核** | 历法类型、闰月、日期换算、跨年或干支尚未独立核对 | 不生成用于计算的确定日期 |
| **地点待核** | 尚未证实出生地，或仅有区域而无坐标 | 不自动精确落点 |
| **存在冲突** | 日期、干支、地点或版本互相矛盾 | 保留各说，禁止静默选一个 |

“已核实”在本文只覆盖明确列出的字段与证据，不表示整条人物资料已达到上线标准。所有网页访问与工具状态均为本次研究时点的结果。

## 5. 入库与历法交接规则

### 每条记录至少交付这些字段

1. 稳定 ID、人物 / 事件名称、异名、关联人物 ID。
2. 原始日期原文、原始历法、年号及年次、月日、是否闰月、日干支、是否为推算、精度和争议。
3. 西历输出采用 `julian`、`gregorian` 或 `proleptic-gregorian` 明确标记；另存统一日序 JDN / JD、换算实现及版本、完整参数和交叉核验结果。JD 须说明正午起算，日期边界不可错半天。
4. 原始地名、地点类型（出生 / 籍贯 / 任职 / 事件发生 / 记载）、历史有效时期、古今地名证据、经纬度、坐标系、精度半径或区域。河中出生等记录可保留区域，不伪造一个精确点。
5. 时间精度 `date-only / night / dawn / hour-range / exact`；当地计时制度和 UTC 换算依据。没有时辰时不保存“00:00”作为史实；供观天使用的示范时刻放在独立用户选择字段中。
6. 出处标题、作者、版本、卷页、短摘录、直达 URL、访问日期、利用许可；冲突证据分别保存。
7. 日期、地点、文本版本、许可四项各自的核实状态、审核人 / agent 与核验日期。

### 必须守住的换算边界

- 历史中国日期不是把“农历”交给一个仅支持近现代年份的 npm 库就能解决。历制、朔闰、改历和史料记日均须核对。
- 1582 年不是全球统一改历日。英国牛顿的旧历生日例子必须保留 1642-12-25 Julian / 1643-01-04 Gregorian 两种表示。
- 生日原历年可能跨到下一西历年；日精度不表示时间、时区精度也达到了分钟。
- 本项目 `src/astro/ephemeris.ts` 的 `toUTCFromLocal()` 现用经度约算时区，不能直接用于历史民用时。`Date.UTC()` 对 0–99 年还有特殊处理；未来日期适配器应显式构造年份并带历法标签。
- “历史上的今天”要先明确比较规则：统一公历月日、原历月日或用户选择的历法周年。不要在一个结果列表中混用三种规则而不说明。
- 星空结果是该日期 / 地点 / 假设时刻的天文重建，不自动证明某人当时看到了月亮，也不重建未经史料证实的天气、遮挡与光污染。

## 6. 星座 / 星宿渲染方案

### 6.1 采用的技术组合

沿用现有 **Three.js + React Three Fiber + astronomy-engine**。星表和文化层是数据模块，场景只负责绘制。一个视图内保持一个 WebGL renderer，后续沿用已有分辨率预算、隐藏暂停、截图与玻璃合成机制。独立 spike 的单 canvas 验证不代表已经接好了主场景玻璃合成器。

| 层 | 采用方案 | 证据与边界 |
| --- | --- | --- |
| 恒星目录 | [HYG v4.4](https://codeberg.org/astronexus/hyg)，提取亮星，并保留所选文化连线引用的较暗星 | 原始约 119,614 条，RA 为小时、Dec 为度，J2000；`hip` 才是 HIP 关联键，`id` 是 HYG 自己的编号。数据 CC BY-SA 4.0，需保留归属与衍生数据许可 |
| 中国文化层 | [Stellarium 的宋代星官数据](https://github.com/Stellarium/stellarium/tree/master/skycultures/chinese_song_dynasty)先做 spike | 数据含 HIP 连线、中文名及二十八宿距星。说明以 1052 年观测与《新仪象法要》等重建，许可 CC BY-SA 4.0；这是现代整理的历史重建，不能当原始宋代观测值本体 |

**注意数据计数：** 宋代说明称 283 星官、1464 星（含 M7、M44 星团），而 JSON 的渲染条目可以更多；不能把条目数当作古代星官总数。二十八宿不是把圆周平均分为 28 份；距星与时代有关，觜、参尤其要核。不在 spike 中未经验证就宣称“月亮精确落在某宿”。

本次实际读取的宋代 `lunar_system.comment` 明确含 **“Needs confirmation”**。该限制保留在衍生数据中，而非删除标记后对外宣称已核实。HYG 与文化层的关联还发现 HIP 55203、78727 无直接记录；详见下面 spike 数据结果中的显式成分星代理。

### 6.2 数据与坐标接口

```text
历史记录 → 日期适配器（历法 / 时间精度 / 观察时刻假设）
                                  ↓ explicit UTC + observer(lat, lon, height)
HYG J2000 + velocity → 恒星自行传播 → astronomy-engine EQJ→HOR → World
文化包（id / 年代 / HIP 连线 / 中文名 / 距星） → HIP 索引关联 ─────┘
                                  ↓
批量星点 + 批量连线 + 有上限的文字标签 → 单 R3F Canvas
```

- 本次 spike 的 World 定义：`x = East, y = Zenith, z = South`，相机北向看 `−Z`；由 HOR 的 `(North, West, Zenith)` 转成 `(-West, Zenith, -North)`，保持右手系。
- 自行由 HYG 的 J2000 笛卡尔位置与 pc/year 速度传播后归一化；无可靠距离 / 速度时回退目录方向并明确计数。岁差、章动和地球自转由日期旋转承担，不把“旋转一张银河图”称为天文复原。
- 简单线性传播是 spike 的可审查模型；数千年精度、测量误差、双星、视差、年周光行差、历史 ΔT、折射等必须在正式准确度声明前单独评估。不得承诺分钟级古代指向。
- 每个数据包带版本、上游固定提交、SHA-256、字段单位、筛选规则、许可与归属。衍生数据与应用代码分别声明许可，不随应用代码许可证自动换许可。

### 6.3 与现有产品的关系

1. 现有地月构图保持用户已确认参数；原有 Moon / Earth 镜头是经过设计的构图，不能当作地面真实方位。
2. 恒星背景层后续可替代目前的星空摄影贴图。需要专门核相机、场景整体对齐与惯性星空之间的关系，不能把新地平星空直接贴进已旋转的地月组。
3. 真正的地面观天视图另设明确入口，共享日期地点，采用物理星历和地平线；进入 / 返回应恢复原构图。
4. 交互借鉴 [Star Walk 时间选择](https://starwalk.space/en/tutorials/how-to-set-the-time-and-date)与[官方手册](https://vitotechnology.com/assets/manuals/starwalk2_manual_en.pdf)：时间、拖动、选择星官、少量说明。这里参考交互，不假设其有可嵌入的公共 SDK。
5. 出生日只有日期的记录，观察钟点由用户选择并标注为演示假设。古人所见、同一天的现代夜空、周年日期分别说明。

### 8.1 帧率排查与修正

发现并处理的实现问题：

- 原来虽然配置了按需渲染，另一个持续动画回调仍不停请求重绘；现在静止时停止绘制，只在操作、时间 / 地点 / 数据改变、缩放和尺寸变化时更新。
- 连续测量只使用 R3F 的帧循环。30 Hz 节拍按截止时间推进，错过时跳过旧时隙；使用与浏览器动画回调一致的 `DocumentTimeline` 帧时间安排绘制，避免 CPU 回调排队把帧间隔变成 16 / 50 ms。无该 API 时回退到普通时钟。
- 名称投影仅在视向、视场、尺寸、文化数据或遮挡改变时更新；缓存节点，坐标未变时不重复写样式。指标单独订阅，不再通过整页状态更新反复触发画布。
- 热更新时卸载旧根节点，清理旧 renderer / 监听器；相机配置保持稳定，避免修改控件时重新套用初始视场。隐藏时暂停并重置采样，恢复时重新开始统计。

## 9. 2026-10-22 星点视觉迭代

本轮用户授权：先改善独立 spike 的星等、颜色、缩放后星点表现，参考 Stellarium / 同类星空应用，要求可辨的亮暗、冷暖及艺术氛围，自己验证后展示。**未接入主页面，未提交、推送或发布。** 第 8 节记录上一轮基线，本节记录新的视觉实现与验收。

### 9.1 设计与模块边界

- 延续深蓝背景与现有界面；亮星用细亮核心、带本色的柔光及少量短光芒，暗星保持细点。没有增加随机星、摄影星空底图或新的连续动画。
- 新增 `src/spikes/sky/starAppearance.ts`，提供 `StarAppearance`、默认强度、B−V 显示色与 `createStarMaterial(maxPointSize)`。星点仍只占一次绘制；`SkyObjects` 负责目录属性与材质参数，颜色缓冲不因日期改变而重复生成。
- `src/spikes/sky/main.tsx` 仅增加样机调节项。原来的“星点深度”改称“最暗可见星”，避免与亮度调节混淆。默认：星光亮度 **1.00**、冷暖色彩 **1.1**、柔光强度 **0.85**；目录截止仍为 6.5 等。
- 不改星位、星等、B−V 源数据、历法、自行算法、星座 / 星官连线或插画锚点。`src/main.tsx`、`SimpleTest`、正式渲染流程和仓库原有 `dist` 未由本轮修改。

参考的是官方 [StelSkyDrawer 接口](https://stellarium.org/doc/head/classStelSkyDrawer.html)中点光源的相对 / 绝对尺度、光晕及缩放适配思路，并核对了 [v26.3 实现](https://github.com/Stellarium/stellarium/blob/v26.3/src/core/StelSkyDrawer.cpp)。本轮材质和色板独立编写，没有复制该程序的渲染代码或颜色表；未重新运行桌面端做逐像素视觉比对，也不宣称复刻了其完整大气与视觉适应模型。

### 9.2 星等、颜色与缩放策略

星等使用目录 V 值，并将光通量作 0.60 指数的感知压缩。亮星通过核心面积与柔光范围体现差异，避免只有统一封顶的不透明度。所有显示强度都是感知设计，**不是校准测光，也不表示恒星真实角直径**。

B−V 显示色由蓝白、近白、暖黄到橙红连续插值，并正确处理输出色彩空间。只有最中心的小区域趋白，外围保留本色；否则低屏幕密度下整个核心泛白，会再次冲淡冷暖。缺少 B−V 时用中性白，不替数据猜测颜色。颜色和星等仍是固定目录值，没有新增变星或随年代改变本色的模型。

缩放直接读取当前投影矩阵，不依赖手势结束后的 React 状态。星点大小以屏幕像素控制，适度增强细节与光量，并限制在硬件点精灵尺寸内；没有增加新的帧循环。1 等星的 GPU 探针中，视场从 110° 缩至 25°，半光半径约从 **1.58 增至 2.12 CSS px**，保留点光源观感。

原有 `scripts/test-sky-spike.mjs` 的 **13 组回归通过**，TypeScript 检查及独立生产构建通过。原有古代双星未完全对齐的报告状态保留；本次视觉调整没有解决或掩盖它。构建仍提示大 chunk，资源拆分和网络冷启动仍待后续处理。
