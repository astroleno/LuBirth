- 视觉：延续现有暗色玻璃界面；loading 使用短句手写显现，纪念卡上部完整保留地月截图，下部以纸色留白承载同源笔迹和可选择的普通文字。
- 交互：每次 loading 只展示一套模板，约 2–3 秒自然显现；场景就绪即可淡出，不为动画额外延长加载，减少动态时静态显示。截图预览提供“制作纪念卡”，可切换模板、调整文字大小和位置、选择时间地点及署名，预览后保存 PNG。

- 素材：Inko scene 是字形位图及排版数据，没有笔画中心线。SVG 使用同源笔迹与逐字遮罩，若另作逐笔路径则明确为后制编排；保留原始标识与来源字段，不以系统字体冒充生成笔迹。
- 验收：三套模板在 loading／纪念卡均可用；真实就绪与减少动态策略有效；草稿不受后续场景变化污染；个人／示例／历史与默认当地 20:00 的说明正确；PNG 标识回读、透明边缘、窄屏保存、键盘焦点与资源释放通过。仅改独立模块及 loading／截图入口，避免干扰主线程正在进行的地月修复。

- `public/keepsake/templates/v1/`：三套 PNG、静态 SVG、loading SVG、原始标识图和来源清单。SVG 嵌入 scene 的原字形 alpha，使用逐字遮罩，不依赖在线接口，也不宣称还原真实笔顺。

## 后续扩展方案：自定义手写与服务端任务

以下为原方案的扩展设计，不属于本次固定模板交付或其验收范围。当前没有部署自定义生成服务、持久化私人草稿或发布网站。

## 目标与使用场景

把用户已经看到的地月画面，做成一张带手写祝福的出生纪念卡。地球、月相、出生地和时间继续由 LuBirth 的天文状态决定；Inko 负责用户确认的文字笔迹，卡片在浏览器合成。

适合生日赠礼、父母写给孩子的话、写给过去或未来自己的短笺。建议首次提供一张完整卡面：上部保留地月画面，下部承载短寄语，日期、地点、时间解释与署名作为清晰的普通文字。具体祝词由用户输入或确认，示例不直接成为正式文案。

目前截图输出当前画布的 PNG，没有祝词编辑器、手写任务或纪念卡排版器。截图的像素尺寸取决于实际画布，不能直接承诺印刷精度。

## 用户流程

1. 用户确认出生信息并选好画面，在截图预览选择“制作纪念卡”。
2. 立即冻结截图、观测状态、月球展示模式和画面版本，形成独立草稿。后续浏览场景不会悄悄改写草稿。
3. 用户输入寄语，选择是否显示出生钟点、城市及署名。默认只显示自己明确选中的信息。
4. 显示将发送给 Inko 的确切文字、笔迹样式和实际费用信息。默认只发送寄语；出生坐标、照片和截图不随任务上传。
5. 用户主动生成。等待期间可继续编辑、返回观看或取消等待；原始截图始终可保存。
6. 结果就绪后在本地合成，允许调整文字位置和大小，再导出 PNG。没有改字的排版调整复用同一笔迹。

固定祝词可以在发布前生成，用户访问时直接读取缓存。任意自定义新文字仍需要云端生成；本地排版不等于本地模型推理。

## 模块设计

以下名称均为拟新增模块。

| 模块 | 职责与关键接口 |
| --- | --- |
| src/keepsake/draft.ts | captureKeepsakeDraft：保存截图、Observation 副本、展示模式、文案与修订号 |
| src/keepsake/layout.ts | layoutBirthCard：计算画面、寄语、元信息及生成标识的安全区 |
| src/keepsake/compose.ts | composeBirthCard：在独立二维画布中合成，不操作地月场景相机 |
| src/keepsake/handwriting-client.ts | createJob、readJob、stopWaiting：访问自有服务，过滤过期结果 |
| src/components/keepsake/KeepsakeEditor.tsx | 输入、外发文字预览、任务状态及保存 |
| src/keepsake/png-metadata.ts | 在本地写入最终 PNG 的生成标识并回读校验 |
| services/handwriting | 网站外的服务端适配器：持有密钥、校验费用、排队、下载和渲染笔迹 |

草稿建议包含 draftId、revision、observation、sceneImage、moonPlacement、message、signature、visibleFields、layoutVersion。服务请求只包含 text、styleId、layoutId、draftRevision、requestId；观测资料保留在本地草稿中。

拟新增网站服务接口：

- POST /api/handwriting/quote：返回可用样式、排版限制及实际报价。
- POST /api/handwriting/jobs：携带有效报价和防重复请求标识，返回自有 jobId。
- GET /api/handwriting/jobs/:id：返回 queued、running、ready、failed 或 expired，以及自有资源地址。

这些不是 Inko 官方路径。服务端再调用官方 POST /generations，并按 2–5 秒间隔轮询上游任务。同一请求断网重试先查已有任务，避免重复生成与收费。取消等待不保证取消上游计算；迟到结果只有在草稿修订仍一致时才可应用。

## 笔迹与卡面合成

Inko 可提供 PNG、PDF 和 scene ZIP。透明文字需要依据 scene 字块和笔触渲染另行输出，并检查细笔画与边缘；不能把纯白阈值删除当作完成透明化。

建议服务端生成经过校对的 RGBA 文字图层，浏览器只下载该图层，再与本地截图合成。服务端无需接收出生信息。照片与文字图层的像素尺寸分别保存，卡面输出不得把较低分辨率截图伪装为高清原图。

保留原截图的构图和色彩。寄语放在画面外的留白区域，避开月球、出生地标和地球边缘。祝词不替代天文说明；合影模式与真实月球位置须在纪念卡元信息中可辨认。

普通文字继续使用项目字体。手写只承载一段寄语，署名是排版文字，不模拟用户或第三方的真实签名。

## 时间与隐私

- 当前出生观察保存在浏览器会话；纪念卡持久草稿属于新增能力，须由用户主动保存，并提供删除入口。
- 个人出生、当前示例和历史演示不能混用。历史卡保留演示钟点、默认 20:00、地方平太阳时或条件日期等实际说明。
- 不知道出生钟点时不得自动补一个时刻后标成真实出生天空。
- 精确坐标默认不印出，也不进入请求日志、分析事件、公开 URL 或共享缓存键。
- 若用户把姓名、生日写进寄语，外发预览须显示这些内容；云端生成是用户对这段选中文字的单独选择。
- 私人任务和结果按访问者隔离，使用不可猜测的资源地址，支持删除；公开固定祝词与私人草稿分开存储。

## 性能 缓存与部署

此前一次 63 字样本从确认到首张完整 PNG 约 15.124 秒，仅说明一次端到端等待。自定义任务按异步导出设计，不把这个数字当作稳定时延承诺。

主场景只在用户取景时调用既有截图接口。文字生成、图片解码和卡片合成不加入 Three.js 每帧循环；退出编辑页释放临时画布、位图和对象 URL。新功能的验收仍需在真实手机测主场景性能，已有笔迹样本不能证明 LuBirth 帧率。

缓存键纳入文案、样式、排版参数、渲染器版本及实际文件哈希；私人缓存限定在用户范围内。改字产生新任务，单纯移动图层不重新生成。上游链接约 24 小时有效、文件约 30 天保留，需及时下载到自己管理的存储，不能把临时地址写进发布资源。

固定祝词与布局清单随 /lubirth/ 静态资源发布。个性化服务单独部署，通过反向代理或受控跨域供网站调用；API 密钥不进入 Vite 构建。供浏览器合成的图片须满足同源或正确的跨域读取条件。

保留 Inko 当前要求的可见生成标识及隐式标识。Canvas 合成会重编码 PNG，最终下载必须调用本地标识写入器，按照官方格式写入并回读校验。该模块属于需要新增的导出能力，完成验证后再开放合成卡下载；完整卡面和截图不为此上传服务器。

## 实施顺序

1. 固定本地草稿、卡片安全区与出生信息显示规则，以已批准的固定祝词资源贯通预览和合成。
2. 完成笔迹资源准备、透明边缘校验、标识写入及既有资源发布适配。
3. 接入个性化任务服务、外发预览、报价、防重复、取消等待与过期处理。
4. 验收个人、历史、合影和真实位置四类情况，再按仓库现有发布要求交付。

## 验收标准

- [ ] 截图与草稿观测状态对应同一时刻，编辑期间切换天空不污染原草稿。
- [ ] 合影位置、真实位置、出生输入与历史演示说明准确，未擅自补齐钟点。
- [ ] 寄语校对无缺字，长文明确分页或提示用户调整，不静默截断。
- [ ] 出生资料、截图和私人照片默认不随笔迹任务上传；实际外发文字可预览。
- [ ] 重复点击、断网、改稿、离开和迟到响应不会重复收费或覆盖新稿。
- [ ] 透明边缘、深浅背景、手机保存和最终 PNG 生成标识均通过验证。
- [ ] 资源域名跨域策略支持本地合成，临时上游链接不成为永久资源。
- [ ] 主场景画质与交互保持，编辑退出后无持续绘制或资源累积。
- [ ] 新增页面完成键盘、屏幕阅读和减少动态检查，任务状态不用假进度。
- [ ] 手机实测、服务器配置和公网文件校验完成后才记录上线通过。
