# LuBirth 沉浸观看与古今发现迭代

Astra 审查并制定两批计划，Sol 实现和实测，Astra 分批独立复核。起点为 main 的 `8e626f35`，以仓库源码、150 条已收录的资料及同一浏览器的前后录制为依据。

## 第一批：地月画面与等待

地月按固定间隔唤醒绘制，浏览器在拥挤时会错过连续的刷新机会。沉浸近景只有地标需要折射，玻璃仍拷贝整张 framebuffer。加入同一浏览器的回调与实际渲染对照，优先优化确定发生的工作。

- `RenderRuntime` 复用 `FrameCadence` 按显示刷新请求目标帧，页面隐藏时停止。维持均衡／省电／细腻的档位、像素预算与材质。开发计时覆盖场景与同一上下文的玻璃绘制。
- `LiquidGlassRenderer` 先投影并排除无效地标。只有一个有效地标且没有 UI 玻璃时，拷贝其折射所需区域并在 shader 恢复原屏幕采样坐标。留出折射、色散和线性插值边距，配合实际 framebuffer 尺寸。旧界面的全屏玻璃路径继续可用。
- `App`、`SimpleTest` 与 `RenderRuntime` 用现有 Observation 标识约束过渡和留念。出生、历史观看或返回地月时，目标观察及其构图已绘制才结束过渡；按现有个人／历史分区保存视角，沿用相机和天体坐标。慢时显示一行状态，缩减动态时直接揭开正确画面。

验收使用同一 H033 承天寺夜游、同一浏览器、档位及视口，记录真实渲染帧、回调、帧间隔、实际 DPR、玻璃取样量及合照首帧。桌面与手机视口看蓝弧、月球明暗、星图及地标，复核画外和边缘。快速换场、旧观察的回流、不同分区的构图及留念使用同一观察。帧率受环境限制时，单列能直接核实的成本变化和设备边界。

## 第二批：古今发现与接续

150 条里 121 条集中在清代及清末，116 条有代表点，85 条日期为条件性解释。已有资料包含 8 类年代与地区和原始出处，但目录按日期铺开，条目需要补哪些信息在打开后才知道。

- `historyRelations` 查询覆盖年代、地区和出处标题，原名字／日期／地点／编号仍可查。目录在同一面板提供可直接观看以及少见年代、世界资料的快捷入口，保留现有年月关联、收藏和精确年代筛选。
- `JourneyPanel` 在结果行前置实际观看条件，搜索命中出处时显示直接对应的标题。详情压缩摘要，保留原日期解释、来源与代表点说明，提供浏览同一年代资料的动作。沿用返回焦点、草稿和滚动位置，不新增确认。
- `HistoricalObservation` 继续由 Observation 表单执行一次明确观看动作。事件缺时刻才默认当地 20:00，人物明确选择钟点，缺地点可沿用个人／当前地点或选一个地点。出生、历史、星空和纪念卡都读取同一时地。

验收走可直接看的事件、无代表点事件、人物钟点、条件历法、年代与来源查找、空结果恢复、收藏与详情返回。以实际入库资料和来自同一观察的地月、星空、卡片为证据，记录现有史料覆盖边界。

每批在检查及 Astra 复核后单独提交推送。用独立预览目录构建并验证，原有工作区文件不纳入提交，过程文件结束后清理。
