# 地点检索与星空切换复核

对照版本为 `942d727b`。Astra 制定验收范围并独立复核，Sol 实现地点和星图两批改动。

## 出生与古今的地点检索

原地点索引把内置对象属性当作候选，输入某些字串会中断搜索。带首尾空格的地名、拆开的省市区名称以及部分常用拼音也会漏掉原本收录的地点。

共用选择器以无原型干扰的索引查询原项目坐标表。搜索支持首尾空格、全半角、逗号和斜线分隔的省市区名，以及已收录省名和部分常用城市拼音。分段查询要求各段属于同一条行政层级。北京、杭州的区县后缀别名按已核实名称收录，候选仍显示原表名称和坐标。 [北京市行政区划](https://mzj.beijing.gov.cn/art/2026/7/16/art_9984_692516.html) · [杭州市人民政府公报](https://zfgb.hangzhou.gov.cn/18/106220253/t106220253064/528872.shtml)

| --- | ---: | ---: |
| 复制含首尾空格的「杭州」 | 0 | 14 |
| 浙江 杭州 | 0 | 14 |
| beijing | 0 | 17 |

六组常规查询的候选顺序与基线一致。同名地点按省市区区分，列表最多显示 20 条。旧版会报错的四个查询均走普通空结果。`node scripts/test-location-search.mjs --baseline` 与 `node scripts/test-location-search.mjs` 可复验。13 项现有观察草稿检查通过。

隐藏式 Chrome 153 的桌面和 390 px 手机视口都完成了两条实际操作。古今从「玄武门之变」选择新城区作为演示地点，仅选一次候选即可进入当地 20:00 的合影，取消地点更改后恢复原选择。出生表单可复制带全角空格的「浙江省，杭州市 西湖区」，选中候选后保存合照，实际使用地点表的纬度 30.272934°、经度 120.147376°。

## 地月与观天之间的计算

两种视图原来分别计算同一时刻的 8,947 颗恒星方向。现在每份星表保留最近一次恒星自行计算的双精度方向，地月与观天分别计算自己的投影。更换时刻或自行开关时覆盖上一组方向。关闭自行时，同一份星表的方向可跨时刻使用。每份活跃星表的额外缓存为 214,728 字节，约 210 KiB。每次投影仍生成独立的位置数组。

`node scripts/test-sky-epoch-performance.mjs` 将 14 个现代与历史场景对照 `942d727b`。位置逐字节一致，帧时刻、HIP 顺序与地平计数通过。测试也覆盖同长度的不同星表、相近时刻、历元替换、自行开关以及输出缓冲隔离。Astra 在 Apple M4 上交错执行预热和采样，核得以下 CPU 中位耗时。

| --- | ---: | ---: |
| 同一时刻切换地月与观天 | 1.197 ms | 0.069 ms |
| 同一时刻更换观测地点 | 1.166 ms | 0.074 ms |
| 连续更换时刻 | 1.276 ms | 1.309 ms |
| 新星表首次投影，含建立索引 | 2.540 ms | 2.706 ms |

耗时是本机准备单次投影数据的成本。桌面和手机视口分别从地月往返观天两次。观天的前后截图逐像素相同，两种视图的运行快照中，观测时刻、恒星位置和合影模式一致，地月使用单一方向光。

Astra 另外抽查公元 1、50、1083、1582、1900、1972、2100、2999 年的次月相和节气。范围内的 191 个事件均通过前一秒与当秒的切换检查。2026 年 50 个主要月相和 24 个节气的对表检查也复跑通过。
